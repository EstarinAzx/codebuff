# RD-X-96

## Register

product

## Users

Developers working in a terminal inside their own project. The current fork supports direct API-key providers and subscription OAuth profiles, with model selection and composable coding agents. Source: `.context/overview.md` and the shipped CLI.

## Product Purpose

Let a developer ask for a coding task, inspect the agent's work, and continue using their chosen provider. Launch with `rdx`; retain `cbm` and `codebuff-mod` as compatibility aliases. Keep saved profiles and the existing provider and model commands working.

## Brand Personality

The display identity is exactly **RD-X-96** (no spaces), superseding CBM-01. Keep Ghostline's layout and animated banner, with the user's newer hot-pink/cyan color reference: pink identity and headings, cyan reply frames and code accents, light-gray prose. The terminal canvas remains transparent. `docs/design/cbm-01-request.md` records the original design selection; `DESIGN.md` owns the current visual contract.

## Anti-references

The fork's own animated RD-X-96 banner is part of its identity. Legacy product names remain only where the rebrand spec requires truthful compatibility or provenance references.

## Design Principles

- Put the coding task and its output ahead of decoration.
- Keep commands, provider selection, and credentials stable through visual changes.
- Use RD-X-96 consistently on product-owned visible surfaces.
- Make the design usable at narrow terminal widths as well as on a wide monitor.
- Keep each fork change small enough to inspect during future upstream merges.

## Accessibility & Inclusion

Preserve keyboard operation, readable focus and selection states, light-theme support, terminal color fallbacks, and the existing animation preference. HTML sketches must work with keyboard controls and narrow browser widths. The user did not specify additional accommodations; these are engineering safeguards, not inferred personal needs.
